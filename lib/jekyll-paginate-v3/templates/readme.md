# Generated Templates

This feature automatically generates templates by indexing frontmatter values. (This is the successor to the "AutoPages" feature from V2.)

```yaml
pagination:
  templates:
    generate:
    - items: posts # required. Search Format: what items to consider
      index: tag # optional. frontmatter key(s) to index
      #filters: # optionally filter those items (same format as pagination filters)
      layout: tags.html
      permalink: /tag/:tag/
      title: 'Posts tagged :tag' # placeholders for the indexed keys
    - items: products
      index: category, subcategory # multi-level indexing
      filter: /^s/ # singular 'filter' is a shorthand to apply filter to the indexed frontmatter key(s)
      layouts: [autopage_category.html] # multiple layouts
      frontmatter: # add arbitrary frontmatter
        section: catalogue
      location: # override whether this generated template will be in 'pages' or a collection name
```

Each entry under `generate` provides an instruction for one or more templates to generate.


## Indexing by Frontmatter

If `index` is set, the generator will look in all the items you've identified and index them by the values in the frontmatter key(s) you specify on `index`.

For instance if you look in `posts` and index on `tags`, it might find posts with the tags "cat" and "dog". It will create a pagination template for "cat" and "dog", each of which will paginate posts with the tags "cat" and "dog" respectively.

The `permalink` and `title` strings can use placeholders for every key named in `index`. Placeholder values in the permalink are slugified. You can configure this with:

```yaml
generate:
- items: posts
  index: category
  permalink: /topic/:category/
  slugify:
    mode: default # passed to Jekyll::Utils.slugify
    case: false   # true preserves case
```

### Multi-Level Indexing

You can index on multiple frontmatter keys:

```yaml
generate:
- items: products
  index: category, subcategory
```

This will generate templates for each `category`/`subcategory` combination.

### Index Group Navigation

When templates are generated by indexing frontmatter, this creates a set of related index groups. E.g. you might have a group of indexes (pages 1, 2, 3) for "posts with 'cat' category" and a group of indexes for "posts with 'dog' category".

The `paginator` object on these index pages gains the `groups` and `group` properties. This allows you to navigate between the groups.

* `groups`: Array of objects representing the group that this index page belongs to. Array has an element for each level of indexing (highest level first). Each element has:
  * `key`: frontmatter key whose indexing generated this group.
  * `current`, `next`, `prev`, `first`, `last`: the current, next, previous, first and last group, where each has:
    * `num`: 1-based group number.
    * `page`: page/document object for page 1 of that group (not set for `current`).
    * `count`: number of items in that group.
    * `start`: group start label/value.
    * `end`: group end label/value (omitted for open-ended groups).
* `group`: shortcut to the deepest entry of `groups` (`groups[-1]`).

The order of groups is determined by the sorting order of the frontmatter key that was indexed.


## Ranged Group Indexing

Generated templates can index frontmatter keys by ranges/bins instead of one-template-per-unique-value.

```yaml
generate:
- items: posts
  index: size # numeric frontmatter key
  group: 100 # index 'size' into bins of size 100
  permalink: /size/:size/
  title: 'Size up to :size'
```

This produces index groups where `0 <= size <= 100`, `100 < size <= 200`, etc.

You can group frontmatter keys that are numeric, date/time, or string (into alphabetical groups).

If indexing multiple keys, the `group` option must be sub-keyed by the frontmatter you want to group:

```yaml
generate:
- items: posts
  index: category, size, date
  group:
    # Don't group 'category'
    size: 100 # group 'size' into bins of 100
    date: year # group 'date' by year
```

The group definition can be given as:

* Just the group size, e.g.
  * `100`
  * `year`
  * `aa`
* Full group definition:
  
  ```yaml
  group:
    step: 10 # required: size of bins
      # all other keys optional
    start: 5 # first group lowerbound
      # start: 5, step: 10, means first group would be 5–15
    grow: 2 # step size multiplicative factor
    min: 10 # minimum step size after growth
    max: 1000 # maximum step size after growth
    total: 8 # max group count; final group is unbounded
    empty: true # emit empty groups too
  ```

The size of groups can change from group 1 to n. This can be controlled either by:

* `step`: set to array, e.g. `[10, 100, 1000]` to manually specify how the step size changes. In this example the first group would be size 10, the second size 100, and thereafter groups are size 1000.
* `grow`: group size is multiplied by this number at each step. Thus `1` (default) is linear (no growth), `2` means group sizes keep doubling, `0.5` means they keep halving, etc. To prevent group sizes becoming too big/small, use `max` and `min`.

### Date/Time

If indexing over frontmatter values that are dates/times, you can use `year`, `month`, `day`, `hour`, `minute` and `second` keywords:

```yaml
group: year
# or
group:
  start: 2026-12-12
  step: month(2)
  min: 1
  max: year(5)
```

* `day(x)`, `month(x)`, `year(x)`, `hour(x)`, `minute(x)`, `second(x)` mean x of that unit. Omit `(x)` to mean one unit.
* If you don't use one of these keywords, numeric values are interpreted as number of days.

`start` also supports:

* `now`/`today` with optional offsets e.g. `now-1` (current time with seconds offset) or `today+2` (current day with day offset)
* `year(today)`, `month(today)`, `hour(now)`, `minute(now)` mean the start of that unit from the present moment. For instance if today is 25 February 2026, then `year(today)` is 1 January 2026 while `month(today)` is 1 February 2026.

#### Alphabetic

String frontmatter values can be indexed into alphabetic groups.

```yaml
group: a
# or
group:
  start: aa
  step: 2
  other: '0-9'
```

`a` and `aa` in the examples above are specifying the starting point for alphabetical grouping, and whether we consider just the first letter, first two letters, or first three (`aaa`) which is the maximum.

Items that have a value that isn't alphabetical, e.g. numerical, are discarded. However if you set the `other` key they will instead be grouped into an "other" set with the name you give.


## Examples

You could generate pagination templates very specifically with a filter, for instance:

```yaml
generate:
- items: products
  index: category
  filter: coats, boots
  # generates 2 templates: products with "coats" category, and products with "boots" category
- items: tools, regions
  # generates 2 templates: one for the "tools" collection and one for the "regions" collection
```
